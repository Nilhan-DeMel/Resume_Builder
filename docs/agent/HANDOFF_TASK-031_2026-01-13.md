## Summary

Implemented robust editor flow: "Upload → Extract (Real) → Label/Structure → Edit (No Blank Screen)".

## What Changed

1. **Extraction**: Replaced stubs with `src/vendor/` libraries for PDF (`pdf.js`) and DOCX (`mammoth.js`).
   - `src/js/upload/textExtractor.js`: Dynamically loads these scripts.
2. **Labeling**: New `src/js/cv/labeler.js` normalizes text and heuristically tags sections (CONTACT, EXPERIENCE, etc.).
3. **Editor**: Created `src/js/views/editorView.js` which:
   - Populates textarea with `cvState.editedText` (labeled).
   - Injects "Optimize Now" button if missing.
   - Wires optimization trigger.

## New Files

## How to Test

1. **Upload PDF/DOCX**:
   - Drag & drop a real resume.
   - Verify green check (TASK-029).
   - Click "Start Optimization".
2. **Editor Verification**:
   - Textarea is **NOT blank**.
   - Content has `[CONTACT]`, `[EXPERIENCE]` tags.
   - Content is clean (no "Page 1 of 2").
3. **Optimize**:
   - Edit the text (e.g. change name).
   - Click "Optimize Now".
   - Should navigate to Processing -> Output.

## Technical Notes

- **Vendoring**: PDF.js and Mammoth.js are stored in `src/vendor/` to avoid runtime CDN dependency.
- **Fallback**: If extraction fails or file is image, it throws error (handled by UI). Binary files are detected.

## Blockers

None. Editor flow is now fully functional for text-based resumes.
